# Engineering and evidence limits

The deterministic baseline has direct access to a fully specified policy. On this task it can be more useful than an agent. Typed records and a strict reference contract make interpretation and output discipline measurable, while reducing the need for general language understanding.

The two actual treatments differ in prompts, role scope, context construction and fixed budget partitions. They do not isolate agent count as a causal variable. Split review cannot borrow an unused role allowance. CPU inference is serialized, so these results cannot establish parallel speedup.

The authored sample contains six mechanisms and twelve paired held-out cases. The split prevents direct lineage overlap within this experiment, not future contamination after publication. Results apply to the frozen artifact and decoding settings. Exact paired counts and descriptive intervals remain small-sample evidence.

Scripted fault tests verify specified invariants and use synthetic assessments. They do not measure model reasoning, production availability or recovery on arbitrary infrastructure. A fresh independent read is required for every claimed recovery result.

The public report is usable without the live API. That does not satisfy live API acceptance. The database binding and public access change require specific authorization after automatic review rejected them.

The private latent answer key and original generator remain local. Public runtime records are inspectable, but an independently repeated latent-truth generation requires the retained local files or explicit authorization to publish them.

Public-record grading is a provisional fallback while local execution is unavailable. It independently applies the declared policy and validates execution receipts, but does not repeat agreement with the separately retained private latent answer key. Reports expose this distinction and keep release completion pending.

Portfolio experiment on authored synthetic release evidence. No production release is assessed or changed. Actual model runs, deterministic decisions and scripted runtime tests are reported separately. Results apply only to the declared cases, model, budgets and execution environment.
