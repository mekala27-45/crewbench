# Task and evidence contract

Sample Service has unit_tests, api_tests, artifact_match and staging_probe checks. Only current case and snapshot records for the target revision count. Notes are untrusted. Both pass and fail means conflicting_current; no matching record means missing_current. Any uncontested current_failure requires hold. Otherwise any missing or conflicting state requires unknown. Otherwise ready. Reasons must include every nonpass check exactly once.

The submission gate checks shape, scope and receipt support. It does not correct the verdict or reason set. The independent Python grader compares the immutable output to latent truth and independently reconstructed evidence. A structurally accepted wrong answer remains wrong.

The catalog omits state and body. read_evidence returns at most four exact records. Missing claims cite the complete catalog. Positive and conflicting claims cite current read receipts. The synthesis role can cite only its own reads or canonical receipts transferred by the join.

Every external provider attempt reserves model calls, canonical transmitted input bytes and a fixed output token allowance in one locked transaction. Output reservation is nonrefundable. Every emitted tool request is counted, including schema failures that Eve never dispatches. Duplicate delivery of the same operation is not a fresh model request. Usage absent from the provider remains null.

There are 48 lineages, 24 development and 24 held-out. The committed subset names 12 held-out cases, two per family. Both actual methods have equal aggregate ceilings and fixed role partitions. One provider request is active at a time. Counterbalance method and specialist order by the registered case order.

Strict success combines verdict, four states, exact reasons, valid references and accepted output before the persisted deadline. Failure, timeout, cancellation, uncertain dispatch and unexecuted rows remain in the denominator. A method must achieve at least 8 of 12 strict successes with zero accepted unsupported-ready decisions to meet the utility floor.

The live demo is baseline only. Provider credentials and generic agent routes are absent from its image. Session capability digests are persisted, never plaintext capabilities. CORS allows the exact Pages origin and localhost development origin. Direct clients still require the capability.


Portfolio experiment on authored synthetic release evidence. No production release is assessed or changed. Actual model runs, deterministic decisions and scripted runtime tests are reported separately. Results apply only to the declared cases, model, budgets and execution environment.
